# [PRD v3.2] 스포스위치 (SpoSwitch)

> 개정일: 2026-09-13  
> 문서 성격: 최신 요구사항과 단계별 구현 계획  
> 서비스 범위: 서울특별시 Android MVP  
> 대응 설계: [스포스위치 설계 문서 v2.0](스포스위치_설계문서_v2.0.md)

## 1. 문서 기준과 개정 이력

이 문서는 기존 PRD v3.1, 기존 통합 설계 문서, 이후 사용자가 설명한 앱 흐름을 통합한다. 내용이 충돌하면 최신 사용자 요구사항을 우선한다. 과거 문서의 ‘코드 생성’ 지시나 검증 완료 주장은 현재 구현 완료 또는 이번 작업의 실행 지시로 해석하지 않는다.

| 구분 | 의미 |
|---|---|
| 확정 요구 | 사용자가 명시한 서비스 흐름 및 범위 |
| 구현 기준안 | 이 문서에서 권장하는 구현 방향. 실제 구현 전에 계약으로 확정 |
| 검증 필요 | 원천 API, 데이터, 환경 또는 제품 정책 확인이 필요한 사항 |

현재 프로젝트에는 기능별로 분리된 네이티브 View UI 목업이 있다. 실제 위치·날씨·운동 데이터, 백엔드, DB, 실제 동영상, 지도와 FCM은 아직 연결하지 않았다. 본 개정은 문서 작성이며 구현 완료 보고가 아니다.

### 2026-09-13 확정 정책

- 서울 MVP의 체육시설 추천에는 공공시설과 민간시설을 모두 포함한다. 시설 유형과 운영 주체는 원천에서 확인 가능한 범위로 표시한다.
- MVP는 로그인 없이 동작한다. 프로필·최근 위치·사용자 설정은 사용자 기기에 저장하며, 로그인과 계정 동기화는 팀 논의 후 후속 범위에서 결정한다.
- 날씨와 대기 상태가 활동하기 좋으면 실내·실외 시설을 같은 비중으로 추천한다. 비·눈 또는 미세먼지로 실외 활동이 어려우면 실내 시설을 우선 추천한다.
- 비·눈의 원천 코드와 미세먼지의 정확한 전환 등급·수치는 M2 데이터 검증에서 확정한다.

| v3.1 대비 변경 | v3.2 기준 |
|---|---|
| 온보딩 후 홈 | 홈에서 위치·날씨를 먼저 확인한 뒤 상태 입력 |
| 연령대·운동목적만 입력 | 성별·연령대, 키·몸무게, 운동 목표를 3단계 입력 |
| 운동 목표와 체력요인 혼용 | 사용자 목표와 매칭 체력요인 구분 |
| 단기예보를 실시간 날씨로 설명 | 관측값·예보값·기준 시각 구분 |
| 공공시설로 단정 | 공공·민간 시설을 모두 포함하고 확인 가능한 유형·운영 주체 표시 |
| 위치·FCM 등록 필수 온보딩 | 프로필, 위치, 알림 권한 및 토큰 등록 분리 |
| GOOD/BAD 이분법 | 정상·악화 판단과 데이터 부족·오래됨 상태 분리 |
| 일괄 자동 스위칭 개발 | 실제 환경 → 프로필 → 운동 → 시설 → 알림 순으로 구현 |

## 2. 제품 목표

사용자의 현재 지역과 날씨를 보여주고, 입력한 운동 목표에 맞는 국민체력100 운동 콘텐츠와 운동 동영상을 제공한다. 여기에 위치와 날씨를 반영한 운동 시설을 추천하고, 날씨가 악화되면 실내 대안을 자동으로 안내한다.

핵심 타깃은 비·눈·미세먼지 등으로 운동 장소 선택에 불편을 겪는 서울 시민이다. 초기 MVP에서 자동화하는 것은 환경 판단, 추천 전환, 알림이며 최초 설정이나 실제 운동·시설 이용을 사용자 개입 없이 수행한다는 의미는 아니다.

### 성공 조건

- 프로필 입력 전에 홈에서 실제 위치 또는 사용자가 선택한 지역과 최신 환경 정보를 확인한다.
- 3단계 입력을 마치면 선택한 목표와 추천 근거를 확인할 수 있다.
- 실제 국민체력100 콘텐츠를 조회하고 제공 영상 또는 대체 링크를 이용할 수 있다.
- 반경 3km 내 조건에 맞는 시설을 지도·목록으로 확인한다.
- 정상 날씨에는 실내·실외 시설을 같은 비중으로 제공하고, 날씨 악화 시 실내 시설을 우선한다.
- 알림 동의 사용자에게 추천 전환 알림을 중복 없이 보낸다.
- 위치 권한 거부·API 장애·추천 없음이 앱 사용 중단으로 이어지지 않는다.

## 3. MVP 범위

### 포함

- 홈 우선 진입, 위치·행정동 표시, 기온·날씨·대기 상태·자료 기준 시각
- 성별·연령대·키·몸무게·운동 목표 입력, 저장, 수정
- 국민체력100 콘텐츠에 근거한 운동 추천 및 영상 조회·재생
- 서울 내 실내·야외 시설 검색, 반경 조회, 시설 상세, 지도 및 외부 길안내
- 날씨 기반 추천 전환, FCM 수신 설정, 토큰 갱신, 알림 진입 처리
- 로딩·오류·빈 결과·자료 누락·이전 자료 표시

### 후속 범위

- 전국 서비스 확대, 지속적인 백그라운드 위치 추적
- 운동 이력 통계·장기 프로그램·웨어러블 연동
- 로그인·계정 동기화 및 여러 기기 간 프로필 복원
- 시설 예약·결제·실시간 혼잡도
- 별도 근거가 필요한 운동 강도·세트 수 자동 산출

시설은 공공·민간을 모두 포함한다. MVP에서는 로그인과 서버 사용자 계정을 만들지 않고 프로필·최근 위치·설정을 기기에 저장한다. 지도·주소 변환 공급자와 FCM 사용 시 계정 없는 기기 등록 방식은 결정 목록에서 관리한다.

## 4. 사용자 여정

```text
앱 실행 → 홈의 위치·날씨 영역 표시
  ├─ 위치 허용 → 취득 좌표를 지역명으로 변환 → 최신 환경 조회
  └─ 거부·취득 실패 → 수동 지역 선택 → 선택 지역의 환경 조회
                ↓
프로필 미완료 → 성별·연령대 → 키·몸무게 → 운동 목표 → 기기에 저장
프로필 완료   → 저장한 정보와 추천 요약 표시
                ↓
맞춤 운동 처방 → 운동 안내·추천 근거 → 영상 보기
                ↓
위치·날씨·운동 적합성을 반영한 시설 추천
                ↓
시설 지도·목록 → 시설 상세 → 외부 길안내

알림 동의 → 환경 감시 → 균형 추천에서 실내 우선으로 판단 전환
         → 중복 방지 후 FCM → 알림 클릭 → 현재 조건으로 추천 재조회
```

알림 권한은 홈 진입이나 프로필 저장의 필수 조건이 아니다. 위치가 확인되지 않은 상태에서 예시 주소를 실제 현재 위치로 표시하지 않는다. 수동 지역 선택은 ‘선택한 지역’임을 표시한다.

## 5. 기능별 요구사항과 수용 기준

| ID | 기능 | 요구사항 | 완료 기준 |
|---|---|---|---|
| H-01 | 첫 홈 | 위치·환경을 최상단에 표시 | 프로필·푸시 토큰 없이 환경 조회 가능 |
| L-01 | 위치 | 위치 권한과 취득 상태 처리 | 거부·정밀도 부족·시간 초과에 수동 선택 제공 |
| L-02 | 지역 표시 | 예: 서울특별시 양천구 신월7동 | 행정동을 확인하지 못하면 확인 가능한 구 단위로 표시 |
| W-01 | 현재 날씨 | 최신 관측 기온·강수·대기 정보 | 출처와 자료 시각 표시, 예보와 구분 |
| W-02 | 예보·누락 | 예보값 및 이전 자료 별도 표시 | 누락값을 좋음으로 치환하지 않음 |
| P-01 | 상태 입력 | 성별·연령대 → 키·몸무게 → 목표 | 앞뒤 이동, 유효성 검사, 저장 실패 재시도 가능 |
| P-02 | 상태 저장 | 프로필을 기기에 저장·조회·수정 | 재실행 후 로컬 복원, 저장 성공 여부 명확 |
| E-01 | 운동 추천 | 목표·장소·지원 연령 조건 적용 | 추천 이유와 원천 자료 출처 제공 |
| E-02 | 영상 | 실제 콘텐츠 영상·썸네일 표시 | 재생·일시정지·복귀·실패 및 대체 동작 검증 |
| F-01 | 시설 추천 | 공공·민간 포함, 반경 3km, 실내외·종목 적합성 고려 | 거리순 결과, 유형·운영 주체 표시, 적합한 시설 없음 상태 제공 |
| F-02 | 시설 탐색 | 지도·목록·필터·상세 | 같은 조건에서 지도와 목록의 시설 일치 |
| F-03 | 길안내 | 시설 좌표로 외부 지도 연동 | 지도 앱 미설치 시 웹 또는 주소 대체 제공 |
| S-01 | 추천 전환 | 정상 시 실내·실외 균형, 유효한 악화 신호에는 실내 우선 | 비·눈·미세먼지 사유와 자료 품질 표시 |
| N-01 | 알림 | 동의 사용자에게 전환 안내 | 반복 감시·재시도에서 중복 억제, 거부 시 앱 기능 유지 |
| N-02 | 알림 진입 | 종료·백그라운드·포그라운드 지원 | 알림 클릭 후 최신 추천을 다시 조회 |

### 프로필과 개인화

목표 선택은 사용자에게 친숙한 문구로 제공하고 내부에서는 안정적인 코드를 사용한다. 다음 매핑은 구현 기준안이다.

| 사용자 목표 | 내부 목표 코드 | 매칭 체력요인 후보 |
|---|---|---|
| 근력 및 근육 강화 | STRENGTH_MUSCLE | 근력, 근지구력 |
| 체지방 감소 | FAT_LOSS | 심폐지구력, 근지구력 |
| 유연성 및 자세 개선 | FLEXIBILITY_POSTURE | 유연성, 평형성 |
| 기초 체력 향상 | GENERAL_FITNESS | 심폐지구력, 근력 |

원천 체력요인과 연령값을 확인한 뒤 매핑을 확정한다. 연령대의 ‘공통’과 특정 연령 제한을 구분한다. 성별 ‘선택 안 함’을 허용하고, 성별·키·몸무게의 수집 목적과 추천 활용 여부를 구체적으로 안내한다.

현재 목업의 키 100~230cm, 몸무게 25~250kg 범위는 임시 입력 검증값이다. 실제 제품의 연령 범위와 함께 재검토하며 의학적 기준으로 표현하지 않는다. 원천 근거가 없는 경우 키·몸무게로 체력 수준이나 운동 강도를 추정하지 않는다.

### 시설 범위

전국체육시설 원천의 공공시설과 민간 신고시설을 모두 추천 범위에 포함한다. 원천에서 운영 주체 또는 시설 유형을 확인할 수 있으면 화면에 표시하고, 확인할 수 없으면 임의로 공공 또는 민간으로 분류하지 않는다. 모든 결과를 ‘공공체육시설’이라고 통칭하지 않고 ‘체육시설’로 표시한다.

## 6. 환경 판단과 예외 정책

| 환경 입력 | 추천 동작 |
|---|---|
| 유효한 현재 비·눈 또는 전환 기준 이상의 미세먼지 | INDOOR_PRIORITY, 실내 우선 및 확인된 사유 전체 표시 |
| 필요한 입력이 모두 유효하고 실외 활동 방해 조건 없음 | BALANCED, 실내·실외 같은 비중으로 표시 |
| 일부 누락·오래됨, 다른 유효 자료에서 악화 확인 | INDOOR_PRIORITY와 자료 부족 안내 함께 표시 |
| 일부 누락·오래됨, 유효 자료에서 악화 미확인 | UNKNOWN, 판단 유보·이전 결과 표기·수동 시설 탐색 |
| 예보만 강수 예상 | 예보 안내, 현재 비가 온다고 단정하지 않음 |

강수는 선택한 기상 API의 코드 체계에 맞춰 비와 눈을 정규화한다. 미세먼지·초미세먼지의 실내 우선 전환 등급·수치는 M2에서 실제 등급 필드와 공공 기준을 확인한 뒤 확정한다. 누락 또는 점검 값을 수치 0으로 변환하지 않는다.

| 예외 | 사용자 경험 |
|---|---|
| 서울 외 지역 | MVP 범위를 안내하고 서울 지역 수동 선택 제공 |
| API 일시 장애 | 재시도, 이전 자료와 기준 시각 표시 |
| 프로필 미완료 | 환경은 표시하고 개인화 처방은 입력 CTA 제공 |
| 운동 추천 없음 | 허용된 공통 대상 콘텐츠 또는 결과 없음 안내 |
| 시설 추천 없음 | 반경 내 결과 없음 표시, 조건 변경 제공; 자동 반경 확장 금지 |
| 영상 재생 불가 | 실패 안내와 검증된 원문·외부 링크 제공 |
| 알림 거부 | 앱 내 조회·추천은 정상 이용 |
| 오래된 위치 | 갱신 안내, 유효 기간을 넘긴 위치로 자동 알림 금지 |

## 7. 데이터와 품질 원칙

- 국민체력100 동영상 정보는 콘텐츠 조회용 원천이다. 개인별 정밀 처방 산출 기능이 검증된 것으로 간주하지 않는다.
- 운동·시설 정보는 배치 적재하고 기상·대기는 지역별 공유 조회와 캐시를 사용한다.
- 영상 출처를 표시하며, 제공되는 이용조건·재생 URL의 유효성을 연동 전에 확인한다.
- 현재 날씨, 예보, 대기 자료의 시각을 각각 관리한다.
- 시설 사진·요금·운영시간은 실제 제공된 값만 표시한다. 목업 생성 사진을 실제 시설 사진처럼 전환 사용하지 않는다.
- 알림의 판단 기준은 앱 내 추천과 동일한 정책을 사용한다.
- 프로필·최근 위치·사용자 설정은 기기에 저장한다. 서버가 공공데이터 제공을 위해 요청 좌표를 처리하더라도 사용자 계정이나 프로필과 연결해 저장하지 않는다.
- FCM을 사용할 경우 기기 토큰은 로그인 자격이나 사용자 계정으로 취급하지 않는다. 진단에 키·토큰·정밀 위치·신체 정보가 그대로 남지 않도록 한다.

## 8. 작업 순서와 단계 완료 기준

각 단계는 서버 구현과 Android 연결을 하나의 기능 묶음으로 완료한다. 일정은 인원·투입 시간·외부 승인 상태를 확인한 뒤 산정한다.

| 단계 | 선행 | 작업 | 산출물 / 종료 조건 |
|---|---|---|---|
| M1 | 없음 | 요구사항·추천 정책 확정 | 시설 범위·로컬 사용·환경 추천 정책 및 남은 개인화 기준 결정 |
| M2 | M1 | 외부 API·콘텐츠 검증 | 실제 응답 필드표, 원천 값 목록, 영상·주소 변환 검증 |
| M3 | M2 | API·DB 계약 확정 | 계정 없는 API 계약, 로컬 저장 모델, 서버 데이터 모델, 오류·시각 규격 |
| M4 | M3 | 앱·서버 기반 구성 | 기능별 상태·Repository, 서버·DB 실행, 마이그레이션 |
| M5 | M4 | 실제 위치·날씨 | 프로필 없이 실제 환경 표시, 거부·장애 경로 통과 |
| M6 | M5 | 실제 프로필 로컬 저장 | 입력·수정·저장·재실행 복원 |
| M7 | M6 | 운동 적재·추천·영상 | 원천 콘텐츠 매칭, 재생, 빈 결과·실패 처리 |
| M8 | M7 | 시설 적재·추천·지도 | 3km·종목·분류 검증, 상세·길안내 |
| M9 | M8 | 스위칭·FCM | 지역 감시, 상태 전환, 중복 방지, 딥링크 |
| M10 | M9 | 통합·배포 준비 | 실기기 전체 흐름, 장애·호출량·배포 점검 |

첫 구현 묶음은 M1~M6으로 ‘실제 환경이 표시되고 프로필이 저장되는 앱’을 만든다. M7~M8에서 기본 서비스를 완성하고, M9에서 자동 알림을 추가한다.

## 10. 출시 수용 체크리스트

- [ ] 위치 또는 수동 지역을 기준으로 실제 날씨를 표시한다.
- [ ] 프로필을 저장·수정하고 같은 설치에서 재실행 시 복원한다.
- [ ] 정상 날씨에는 공공·민간의 실내·실외 시설을 같은 비중으로, 악천후에는 실내 시설을 우선 추천한다.
- [ ] 추천 목표와 체력요인, 원천 콘텐츠 출처가 일치한다.
- [ ] 원천에 없는 운동 강도·시간·세트 수를 임의로 생성하지 않는다.
- [ ] 실제 영상 재생과 실패 대체 경로를 검증한다.
- [ ] 시설의 서비스 범위·종목 적합성·분류·거리·좌표를 검증한다.
- [ ] 자료 누락을 정상 날씨로 처리하지 않는다.
- [ ] 알림 거부·앱 종료·재시작·토큰 갱신·중복 방지를 검증한다.
- [ ] 보안·데이터 삭제·키 관리·배포 설정을 확인한다.
- [ ] 목업 데이터와 실데이터의 실행 구성을 구분한다.
