# DB 없이 백엔드 실행하기

현재 서버는 사용자 정보를 저장하지 않습니다. 사용자 프로필과 선택 지역은 Android 기기에,
시설 목록은 공공 API에서 불러온 뒤 서버 메모리에 보관합니다. MySQL 설치나 DB 접속 환경변수는 필요하지 않습니다.
기존 `local`, `test` 프로필도 DB 없이 사용할 수 있습니다.

Java 21에서 다음 환경변수를 설정합니다. 인증키는 소스 파일에 작성하지 않습니다.

| 환경변수 | 용도 |
|---|---|
| `KAKAO_REST_API_KEY` | 카카오 지역 조회 |
| `KMA_SERVICE_KEY` | 기상청 및 기본 공공 데이터 인증키 |
| `FITNESS100_SERVICE_KEY` | 국민체력 100 운동 영상 |
| `SPORTS_FACILITY_SERVICE_KEY` | 시설 조회, 생략하면 `KMA_SERVICE_KEY` 사용 |
| `AIRKOREA_SERVICE_KEY` | 대기질 조회, 생략하면 `KMA_SERVICE_KEY` 사용 |

저장소 루트에서 PowerShell로 실행하는 예:

```powershell
# 위 API 키는 실행 환경에 미리 설정합니다.
Set-Location C:\SpoSwitch\backend
.\gradlew.bat bootRun
```

확인 순서:

1. `http://127.0.0.1:8080/actuator/health`에서 HTTP 200과 `{"status":"UP"}`을 확인합니다.
2. `/api/v1/facilities?latitude=37.5&longitude=126.8`을 조회합니다. 첫 로딩 중에는 HTTP 503과 `Retry-After: 5`를 반환합니다.
3. 로딩 후 같은 요청이 HTTP 200으로 응답하는지 확인합니다. API 호출 실패는 HTTP 502이며, 서버는 30초 뒤 다음 요청에서 재호출을 허용합니다.
4. `latitude=999` 또는 `latitude=NaN`은 HTTP 400인지 확인합니다. 시설 상세의 거리 계산 좌표는 두 값을 함께 입력하거나 모두 생략합니다.

시설 데이터를 24시간 이상 보관했으면 조회 시 백그라운드에서 갱신합니다. 갱신 중이나 실패 후에도 기존 목록과 그 목록의 로딩 시각을 반환합니다.
프로세스 재시작 시 목록은 다시 불러옵니다. 헬스 체크의 `UP`은 서버 기동 상태이며 시설 목록의 로딩 완료를 뜻하지 않습니다.

```powershell
.\gradlew.bat test bootJar
```

테스트는 외부 API를 대체하므로 실제 DB나 인증키가 필요하지 않습니다.
Lambda 어댑터와 Afterburner 대응 및 실제 배포는 별도 연결 작업에서 진행합니다.

## 이번 변경의 검증 기록 (2026-09-30)

- 백엔드 테스트 69개 통과 및 실행 JAR 생성. 기본 프로필과 `local`·`test` 프로필에서 DB 없는 서버 기동과 실제 HTTP 헬스 응답을 확인했습니다.
- 시설 첫 로딩·실패 후 재시도·갱신 실패 시 기존 목록 유지, 좌표 범위·NaN·무한대 입력의 400 응답을 검증했습니다. 외부 API 응답은 테스트에서 대체했습니다.
- Android 단위 테스트 15개, 디버그 APK 빌드, Pixel_9 회귀 테스트 5개 통과. 회귀 테스트는 앱 실행, 프로필 저장·복원, 잘못된 영상 URL의 컨트롤 비활성화를 확인합니다.
- Android 린트는 오류 0개·경고 45개입니다.
